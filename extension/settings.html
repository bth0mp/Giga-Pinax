Type cards

Off by default. When on, a card for one catalogue type asks nomisma.org which museum coins of that type have been photographed, and shows up to three of them with the collection that holds each. The photos load straight from those museums’ own servers, which see your IP address as any website you visit does. Nothing about them is saved, and they are never part of Copy summary.

Local catalogue data

  • Reading bundled coverage…

RIC, Crawford, Price and Seleucid Coins lookups use this local data. Bopearachchi references and any lookup the local data cannot answer go online to numismatics.org and nomisma.org. A card built from this data makes no request of its own, unless Show specimen photos above is on: the English Nomisma.org names for every authority, denomination, mint, material and portrait these records carry travel with the package too, under CC BY 3.0, and ruler names on RIC cards come from the Nomisma snapshot in ric-people.js, which takes precedence over the bundled label file. A concept Nomisma publishes no English name for shows as the identifier the record carries, and none is ever guessed.

Backup and import

Keep a copy of your watchlist, auctions, bids, reminders, notes and settings.

A spreadsheet copy of one table at a time, for Excel, Numbers or LibreOffice. Amounts are plain decimals with their currency in the next column and are never added across currencies. A CSV file cannot be imported back; keep a backup for that.

Import method

      A rescue file for support and recovery. It is an exact copy of the stored data, including unsaved drafts, captured page text and request IDs, and cannot be imported as a backup.

      Diagnostics

      Giga Pinax keeps a list of its last 50 failures on this device, so you can paste it into a bug report: when each happened, on which page, in which part (catalogue lookup, acsearch, CoinArchives, local records, page capture or reminders), what kind of failure with its HTTP status, and the extension version. It never holds a search term, reference, web address, record or page text, is never sent anywhere, and is not part of a backup.
