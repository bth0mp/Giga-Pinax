# Giga Pinax

A toolbar extension for desktop Brave and Firefox that looks up ancient coin types, shows session-only acsearch prices, calculates buyer’s premium, and keeps a local auction watchlist. Version **0.27.1** preserves Giga Pinax’s RIC, RRC, SC, Bop, Price, Sear, Krause and other catalogue workflows and adds an **Updates** disclosure that shows the installed version and downloads the current release package from GitHub.

The workspace records lots, alternative priorities, planned and externally active bids, reminders, outcomes, collection history, and collector-entered comparables in USD, EUR, GBP, or CHF. It never places or cancels bids. A resolved reference can be sent to an editable watchlist draft, but fetched acsearch rows, prices, medians, and claims stay only in the current Research view.

## Install

Download the release package for your browser from the [latest GitHub release](https://github.com/bth0mp/Giga-Pinax/releases/latest). This repository is private, so GitHub asks you to sign in with an account that has access. Extract the Chromium ZIP for Brave or Chrome; Firefox can load its unsigned ZIP temporarily. Follow [the installation guide](docs/INSTALL.md).

For later releases, open **Updates** under the popup header and select **Download latest update**. The button downloads the stable package for your browser from the latest GitHub release. It does not silently install files: replace the files in the folder you already loaded and select **Reload** in Brave or Chrome, or load the latest unsigned ZIP again in Firefox.

## What it does

- **Research** retains the complete Giga Pinax reference, type, Recent, CoinArchives, and approved session acsearch workflow. **Calculator** computes hammer plus buyer’s premium with exact minor-unit rounding. **Watchlist** summarizes the next auction, due reminders, and externally active exposure by currency, then opens the full workspace.
- **Save reference to watchlist** transfers only the visible reference, type label, and type-page URL to an editable draft. Current-page capture similarly requires review before lookup or saving. No acsearch result is written into companion storage or backup.
- Saved comparables are collector-entered or separately authorized records. Their median-of-halves statistics remain separate from Giga’s session acsearch interpolation and require at least three included sales for a headline.

- One **Reference** box with **Look up** beside it, the cursor already in it when the popup opens: type `RIC I² Nero 306`, `Titus 123`, `RIC 972`, `Crawford 44/5`, `SC 1266.2`, `Bop Euthydemus I 24A` or `Price 23` and the fields fill in; `RIC 972` lists every type numbered 972 to choose from, and the answer is brought into view rather than left below the fold. An empty box looks nothing up on a freshly opened popup — it says what to type instead, so the number the tool filled in below is never looked up as if you had typed it; fill that field in yourself, or choose a catalogue, and it answers for **Look up** as before. In the empty box the up arrow brings back your recent references, newest first, and the down arrow goes back.
- Any other reference (BCD, HGC, SNG, Sear, RPC…), which has no open type data, gets acsearch prices without a type record: the catalogue becomes **Other (prices only)** and only acsearch is contacted. In the guided **Other** field, references separated by `;` are searched together, each as an exact phrase, so `BCD Boiotia 174b; HGC 4, 1218` finds the lots that cite either. A citation is short, so a `;` part of more than seven words is prose, not a reference: it is left out of the search, and text with no shorter part in it (`Good VF, 3.21 g, 6h, lot 42, from an old album, ex Berk 12 years ago`) is not read as a reference at all — paste the whole lot instead and every reference in it is listed. Typed in the **Reference** box (or right-clicked), the same text is listed reference by reference, and a single RIC, RRC, SC, Bop or Price reference among them is looked up at once. An RPC reference such as `RPC I 1234` or `RPC V.2 1234` also gets an **RPC online ↗** link to its page on RPC Online, which only you open; Giga Pinax never contacts RPC.
- A Sear *Greek Coins and Their Values* reference (`SG 6829`, `SG6829v`, `SG 6829 var.`, `SGCV 6829`, `GCV 6829`, `Sear Greek 6829`) is read as **SG 6829** (a `v` or `var.` becomes **SG 6829 var.**; any other letter stays, as in **SG 6829a**) and priced only, since no open type data carries Sear numbers: acsearch is searched as `("Sear 6829" "SG 6829")`, the two ways dealers cite it, a variety under its type's number. In a lot description `SG 6829v` is listed as **SG 6829 · prices only · var.**
- A Krause & Mishler *Standard Catalog of World Coins* reference (`KM# 123`, `KM 123`, `KM#123`, `KM-123`, `KM.123`, `KM# 123.2a`, `KM# A123`), or the same catalogue's older Y numbering for pre-1901 issues (`Y# 31`, `Y 31`, `Y#59.3`, `Russia Y# 59.3`), is read as **KM# 123** or **Y# 31** and priced only, like SG, since no open type data carries KM numbers. A KM number repeats across countries, so a country typed in front is kept (`Netherlands KM# 123`, `German States Rostock KM# 123`) and narrows the sales. acsearch is searched in its **Modern coins** category as `("KM 123" "Krause/Mishler 123")` — the two spellings dealers cite, with the country in front of the pair — and the CoinArchives link opens that site's **world** section. A Y reference behaves the same way, searched as `("Y 31" "Y# 31")`. Either mixed with an ancient one (`KM# 123; SG 6829`) stays in Ancients.
- Every card has a **Search on CoinArchives ↗** button under **Search on acsearch ↗** (beside it in the right-click window): it opens CoinArchives' own search for the reference in plain words (`Nero 306`, `Crawford 44/5`, `SC 1266.2`, `Price 23`, `Hermaeus Bopearachchi 20`, `Sear 6829`, or an Other reference's first part). It is only a link you open; Giga Pinax never contacts CoinArchives and asks for no permission for it.
- Select a reference on any page, right-click and choose **Look up “…” in Giga Pinax** — it opens in a window you can drag to any size and looks the type and its prices up. Dealer spellings such as `Craw. 44/5` or `Crawford 44/5;` are read, and so is text carrying the hidden characters auction pages add. While that window is open, each right-click looks up in it and brings it to the front instead of opening another. The window button in the header (a square with an arrow) opens the popup the same way, on the type it shows; the toolbar popup's own size is fixed by the browser.
- A whole lot description, pasted into the Reference box or right-clicked (up to 3,000 characters), lists every catalogue reference in it, in the dealer's order: `TITUS, AD 69-79. AR, Denarius. … Ref: RIC 972; Cohen 17; BMC 319.` lists **RIC 972 · Titus**, **Cohen 17 · prices only** and **BMC 319 · prices only**. A lot with one RIC, RRC, SC, Bop or Price reference opens it at once, the list staying above the card; with several, nothing is fetched until you pick one. A RIC number without a ruler of its own takes the ruler named in the lot's heading (`TITUS`, `Titus, as Caesar`) and asks OCRE for that ruler's types, so **RIC 972** there is Titus's denarius under Vespasian; if that finds nothing, the types with the number are offered, never opened. `cf.` and `var.` are shown on their rows, and dates, weights, grades, legends and the provenance tail (`Ex …`) are left out. The keys cover every collecting area a dealer cites: Roman imperial and Republican (`BMCRR`, `RBW`, `CRI`/`HCRI`, `Hunter`, `Woytek`, `LRBC`, `Cunetio`), Roman provincial and the Levant (`Prieur`, `McAlee`, `Varbanov`, `AMNG`, `Lindgren`, `GIC`/`SGI`), Alexandrian (`Emmett`, `Dattari`, `Milne`, `Geissen`), Judaean (`Hendin`, `Meshorer`, `TJC`), Greek (`HN Italy`, `Vlasto`, `ACGC`, `Thompson`), Seleucid and Ptolemaic (`WSM`, `CSE`, `CPE`), Parthian, Sasanian and the East (`Sellwood`, `Shore`, `Göbl`, `SNS`), Celtic (`LT`, `DT`, `ABC`, `VA`), Byzantine (`MIBEC`, `Ratto`, `MEC`), Islamic (`Album`, `SICA`, `Walker`) and world (`Friedberg`, `Davenport`), with the corpora a dealer cites on their own added in 0.26 (`Howgego`, `Pangerl`, `Bodenstedt`, `Ashton`, `Draganov`, `Von Fritze`, `Karayotov`, `Lorber`, `Schindel`, `Saeedi`, `Paruck`, `Vondrovec`, `MACW`, `Cribb`, `Rosenfield`, `MIRB`, `Sabatier`, `Wroth`, `Van Arsdell`, `Delestrée`, `SNAT`, `Klat`, `Balog`, `Goodwin`, `Artuk`, `Vives`). The number is read whichever separator the house writes between it and the key — a space (`Hendin 1188`), a hyphen glued on (`Hendin-1188`, Stephen Album's style), a hash with spaces round it (`Emmett # 874`, the Indian houses'), a dot (`Paruck.285`) or a colon (`SNAT-XIVc:336`) — while a dash where the number belongs still means "not in this reference" and lists nothing (`RIC -`, `SNS--`). A key that is also an ordinary word or an auction house (`Hunter`, `Album`, `Shore`, `Ratto`) counts only with its number straight after it, and never after the house's own name (`Stephen Album`, `Rodolfo Ratto`).
- Guided entry for Price numbers, an RRC (Crawford) number, an SC (Seleucid Coins) number, a Bopearachchi king and number, or a RIC ruler or mint section, volume and number. The ruler is typed with suggestions from every OCRE volume and the volume follows it (**Titus** sets **II.1² (2nd ed.)**; **Hadrian**, found in two volumes, sets **Any volume**); the king is typed with the 48 BIGR kings as suggestions. Whenever the tool moves the volume itself, or clears a ruler the chosen volume doesn't have, it says so in a line under those fields as well as to a screen reader. A blank volume, ruler or king means any, so a number alone lists every type that has it. A reference typed in the Reference box sets the fields to what it says, and a volume it names is never changed.
- Exact-title matching against the ANS search API (SC references are fetched directly by record; Bopearachchi references are verified against the citation in each BIGR record, all in one request, and a series typed without its king lists every king that has it; if that check can't reach numismatics.org, the popup says so rather than “not found”); near matches are offered as a short list.
- Ruler, denomination, mint, material, date range, obverse and reverse legends and descriptions (and the Bopearachchi citation for BIGR types).
- When RIC files a type under a different ruler from the one on its portrait, the card says so in one line: a Caesar's coins sit in the reigning emperor's section, so a Titus lot opens **RIC II, Part 1 (second edition) Vespasian 972** and the card reads *Portrait of Titus, listed under Vespasian.* A ruler and number asked for in the guided fields with **Any volume**, and a lot reference that names a ruler but no volume, are no longer reported as missing: the search is tried once more against the portrait, and a coin from another ruler opens only when the card has that line to explain it *and* the portrait it names is the ruler that was asked for — otherwise it is offered as a choice, as a typed `Titus 972` has always been. Where the volume splits that ruler in two, the same line adds which other section exists (*RIC V also has a Gallienus (joint reign) section.*) — only after the first sentence, so an ordinary card stays quiet. It appears only when the portrait is a ruler RIC itself heads a section with and the card's own section is that ruler, so nothing shown doesn't mean the portrait is the section's ruler: a deity, a name nomisma spells differently, or a volume filed by mint (RIC VI–IX) all stay silent.
- When a type resolves (**Look up**, a choice from a list or a **Recent** chip), acsearch prices are fetched in the same click once acsearch access is granted; edit the acsearch search term and select **Get prices** to re-run it (edited terms are remembered per type). For Bopearachchi types the search starts as `(Hermaeus Hermaios) "Bopearachchi 20"`: the king in both spellings dealers use and the citation as an exact phrase.
- A **Recent** row under the form re-opens your last six types with one click.
- **Alt+Shift+G** opens the popup (change it at `brave://extensions/shortcuts` or in Firefox's Manage Extension Shortcuts).
- A light or dark look: the popup follows your system theme until you select the sun or moon button in the header, and that choice is remembered.
- The median hammer price comes first, under the type and its period buttons, with how far to trust it (`Solid: 22 sales, 2024–2026`: Thin for 1–4 sales, Moderate for 5–14, Solid for 15 or more) and how many matches it was drawn from, lots without a price counted apart from prices that couldn't be counted; then the middle 50% with a range visual and the lowest and highest sale beneath it (`All 22 sales $81–$950`), and an expandable list of the sales linking to acsearch. The obverse and reverse fold away under **Obverse and reverse**.
- Above the median, **All**, **Last 5 years** and **Last 2 years** choose how far back the sales go: the median, how far to trust it, the matches it was drawn from, the middle 50%, the range, **Check a price** and the sale list all follow, and the choice is remembered. Under the median, a trend line sets the last 2 years against earlier sales (`Last 2 years: $250 median, up 18% on earlier sales ($212)`; within 5% it reads `about the same`) whenever each side has at least 3 sales, and **Last sale** gives the date and price of the most recent sale, linked to it on acsearch; neither changes with the period. All of it comes from the one page of results already fetched (at most the 100 most recent sales), so there is no new acsearch request and nothing is stored.
- **Check a price**: type a bid or an asking price under the range and see how it compares, for example `Higher than 7 of 9 sales, 1.6× the median`, marked on the range bar. Nothing is stored.
- **Copy summary** copies the type, median (naming the period when it isn't All), middle 50%, lowest-to-highest range, sale count and how far to trust it, search term, years, last sale, trend, type link (none for an Other reference) and any prices it couldn't count, as plain text.
- Currency USD, EUR, GBP or CHF is passed to acsearch; a price quoted in a different currency is left out rather than mixed in.
- Contacts only `numismatics.org`, `nomisma.org` and `www.acsearch.info` (the last with your own session); the RPC online and CoinArchives links open only when you select them. Your preferences stay in the browser; only the reference or term you look up is sent.

## Checks

```powershell
node --test tests/lookup.test.mjs tests/prices.test.mjs tests/preferences.test.mjs tests/selection.test.mjs tests/catalogues.test.mjs tests/lot.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
npx --yes web-ext@10.6.0 lint --source-dir dist/firefox --warnings-as-errors
```

The runtime has no dependencies. Building uses Python's standard library; `python scripts/make_icons.py` redraws the toolbar icon PNGs from the geometry of `extension/icon.svg` and needs Pillow, a development tool that is never packaged. `web-ext` is used only for validation. Fixtures under `tests/fixtures/` are real API responses captured on 2026-09-10 and 2026-09-11, including a logged-out acsearch page trimmed to three lots and one for a search that found nothing.

Companion JSON backups contain companion records and settings only. Giga lookup preferences, remembered theme, ANS label cache, browser sessions, and live acsearch results are outside the backup. Records created under another extension origin must be exported there and imported explicitly; browser storage does not move between extension identities.
