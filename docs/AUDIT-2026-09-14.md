# Giga Pinax 0.29.0 verification

The six findings and eight workflow improvements approved after the 0.28 review are implemented. Sol agents implemented the changes; Astra reviewed the shared contracts, code and rendered interface. Final approval followed fixes for ordinary-save Undo and a delayed-save race that could otherwise replace a newer draft.

## Completed changes

- Preserve the actual auction URL separately from its canonical URL, carry auction context through capture and Research, and guard repeated or uncertain saves.
- Detect duplicate auction identity inside the serialized writer and offer the existing coin without merging records. Equal references on different auction lots remain separate.
- Curate live acsearch results for a lookup session. Included rows consistently determine the count, range, median, bid comparison and copied summary; fetched rows are not persisted as evidence.
- Add auction queues with explicit event-start versus lot-deadline labels and no invented times for date-only events.
- Calculate buyer premium, shipping, fixed and percentage payment fees, and the highest affordable hammer on a collector-entered fixed bid increment. Save the cost estimate atomically with the planned or recorded bid.
- Compare two to four saved coins, including measurements, condition, cost estimates, photo links and dated, sourced provenance. Photo requests occur only after comparison opens.
- Refresh saved house presets in mounted calculators without replacing dirty inputs. Use a runtime date for evidence filters and update installation and navigation documentation.
- Prepare store listings, privacy disclosures, reviewer notes and required image assets. Preserve existing extension identities and permissions.

Schema version 1, the 5 MiB storage limit, record IDs, revision checks and the queued command writer remain intact. The extension does not place bids.

## Native Brave verification

Tests used isolated profiles and synthetic auction data, without modifying the collector's browser profile.

- An in-place 0.28.0 to 0.29.0 upgrade retained seven existing lots, three events, groups, collection records, preferences and two saved evidence records.
- Real current-page capture preserved the actual lot URL and separate canonical URL. Capture → Research → editable draft → saved coin retained auction context. Double-click and explicit-clear paths passed.
- Duplicate handling worked across views; equal references with different auction URLs remained separate.
- A $100 hammer with 20% premium, $10 shipping, 3% payment fee and $2 fixed fee produced **$135.90**. A $135 budget on a $10 minimum/increment produced a **$90 hammer and $123.54 total**.
- Live preset refresh preserved dirty calculator values. German decimal input with blank optional fees produced the correct total.
- Measurements and sourced provenance survived save and backup round trips. Ordinary-save Undo removed newly introduced optional fields correctly.
- A held post-save snapshot response could not retarget a newer unsaved draft or expose stale Undo.
- Closing-soon filtering and deadline labels matched the saved events. Comparison worked with two and four coins, prevented a fifth selection, and had no outer horizontal overflow at a 390px viewport.
- No remote photo loaded before comparison; unavailable images displayed a fallback afterward. The final desktop calculator displayed its advanced fees in two columns without clipping its result.
- Synthetic prices 100, 200, 300 and 1000 yielded median 250. Excluding 1000 yielded median 200 and consistently updated comparison and copy output. Period changes preserved exclusions; reset, all-excluded and new-fetch paths passed.
- Native import preview/replacement and an actual downloaded full JSON export passed with ten lots and 24 total records. A download problem occurred only in a copied legacy QA profile; the same full dataset imported and exported successfully in a fresh extension profile.
- The final enabled extension reported no manifest or runtime errors.

## Verification limits and distribution status

On 14 September 2026, both live CRRO search and direct `numismatics.org` JSON-LD requests returned HTTP 503. Catalogue workflow verification therefore used repository response fixtures after confirming the live service failure. acsearch curation used synthetic sale rows; authenticated paid-provider sessions were not exercised. These tests establish extension behavior, not current provider availability.

Firefox verification covers lint, core tests and native temporary installation; it does not constitute a complete Firefox UI run. Chrome receives the same Chromium package as Brave but was not separately exercised in native Chrome.

The store materials are ready under [store](store/README.md). Chrome Web Store and Mozilla Add-ons dashboards were signed out, so no submission, Mozilla signature or store publication is claimed. Publisher sign-in and any required publisher details or attestations remain necessary. GitHub Firefox ZIPs are unsigned temporary add-ons. Follow [INSTALL.md](INSTALL.md) and the browser instructions attached to the release.
