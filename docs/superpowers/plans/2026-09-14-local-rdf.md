# Local OCRE RDF Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review these bounded tasks.

**Goal:** Use the supplied OCRE RDF as packaged reference data, keeping auction prices independent and installation limited to the normal extension reload.

**Architecture:** Convert the source once with Python's standard library into a compact candidate index, metadata and volume shards. A lazy local provider serves RIC lookups and saved IDs before permitted online fallback. Reuse the existing RIC matcher, preserve exact replacement IDs, and identify the local source in Research and Settings.

**Tech Stack:** Existing JavaScript modules, static JSON, Python standard library, Node tests, native Brave verification and Firefox package validation. No runtime dependencies or server.

**Spec:** User authorized integration "as seen fit". The design presented in the task limits local coverage to the supplied OCRE/RIC snapshot. Astra reviewed the design before implementation; its main requirements are incorporated below.

## Global constraints

- Release 0.30.0; preserve extension identities and permissions.
- Source file stays unchanged and outside Git. Package derived data and its ODbL attribution.
- The source publication date is unknown; conversion date must not imply freshness.
- Only explicit valid replacement chains resolve aliases. Preserve case, multiplicity and missing fields.
- Never invent Nomisma labels or verified portrait names. Local misses do not prove that a catalogue type does not exist.
- Keep the 0.29.2 price context, curation, copied-query provenance and stale-response protections.
- Local hits make no ANS or Nomisma requests and need no permission. On a miss, already-granted access can provide an online fallback; an explicit Check online click can request access without losing the user gesture.

## Tasks

- [ ] Data: add a deterministic RDF converter, representative fixture and tests for side joins, fields, aliases, malformed input and repeatability. Generate the real snapshot and report counts and sizes.
- [ ] Lookup: add a lazy packaged-data provider, extract/reuse pure RIC matching, integrate local-first type and ID lookup, and test offline hits, ambiguity, corrupted data and fallback.
- [ ] Interface: preserve independent price state, add local provenance and a permission-safe online retry, expose coverage in Settings, and test stale actions and denied access.
- [ ] Distribution: include only validated named data shards in packages, retain browser identities, update installation/privacy/attribution/release documentation and reject unsafe data paths in tests.
- [ ] Verification: inspect the converter and generated data, run all JavaScript/Python tests, validate Firefox, exercise the real packaged extension in an isolated Brave profile and obtain Astra's final review.
- [ ] Release: fast-forward and push main, rebuild the installed Z: folder, publish five browser ZIP assets with installation instructions, and verify public download hashes.
