# Giga Pinax 0.28 design

The user approved all eight recommendations on 13 September 2026. This is implementation authorization, including the established Sol implementation, Astra review, installed-folder update, and GitHub release workflow.

## Product direction

A precise numismatic research tool. Keep the monogram and plum identity. Neutral white/charcoal surfaces, restrained accent, clear type hierarchy, serif only for the brand and coin/reference headings, tabular amounts, readable controls, meaningful separators. Primary actions receive filled buttons; ordinary actions are quiet. No decorative gradients, oversized metrics, artificial imagery, or new runtime framework.

## Required experience

1. One shared visual system across popup, native research panel, workspace, calculator and settings. Readable light/dark themes, keyboard focus, reduced motion, popup 400 by 600, sidebar widths from 320px, workspace from 390px.
2. One reference search followed by its result. Guided catalogue/edition/ruler/number fields live in Refine reference, open on ambiguity or errors in those fields. Preserve existing parsing, choices, recent references, custom terms and request cancellation. Sources stays readily available; settings no longer displaces research.
3. Explicit Open side panel action uses native Chrome/Brave sidePanel and Firefox sidebarAction, with the existing window fallback. The toolbar still opens a quick popup. Reuse popup.html?panel=1. The panel document retains its selected coin, query, results and scroll while other browser tabs are visited; tab changes never silently replace the coin. No fetched price persistence is introduced.
4. Compact watchlist rows show coin, auction/closing date, planned and recorded active bids. A selected coin has one detail pane for its details, notes, bid, attached auction/reminders and outcome. Creation starts through Add coin/Add auction. Small screens use list then detail with Back. Alternatives remain manageable in the list; collection history belongs with outcomes.
5. Price presentation groups median, range, count, period, currency, source and coverage. Show recorded-sales counts rather than treating count alone as pricing certainty. Keep missing/sign-in information and inspectable sale rows. Fetched acsearch prices stay session-only; no automatic CoinArchives paid integration.
6. Foreground the existing page-capture action with an explicit current-page title/source. Capture only following a user action, pin the captured tab identity through asynchronous extraction, retain editable review, and provide Research coin/Save to watchlist. Do not auto-capture unrelated pages or retarget a pending capture after a tab switch.
7. One reusable calculator supports hammer plus buyer premium, maximum hammer from budget, and saved house-premium presets. Use integer minor units and existing forward rounding. The maximum hammer must be affordable under the forward calculation and maximal to one minor unit. Shipping/tax excluded is explicit. Using a preset or calculator result changes draft fields only, never recorded bids.
8. One Settings page owns theme, default bid currency, house premiums, updates and backup/import. Both surfaces use the same Sources control. Plain collector language, visible save/error/retry feedback, keyboard shortcuts and safe Undo for a reversible local edit. Undo never represents external bid cancellation.

## Data and compatibility

- Release 0.28.0; retain extension identities, minimum Firefox142, schema1, host allowlist and existing commands. Chrome adds only sidePanel permission; Firefox uses sidebar_action without Chrome keys.
- Add optional preferences.housePremiumPresets: maximum50 entries { name, buyerPremiumBps }, bounded nonempty house name120, integer basis points0..10000, unique case-insensitive normalized names. Missing on old data reads as empty; preferences.save preserves presets when older callers omit them. Backups include them through existing preferences.
- Add optional lot.notes up to5000 characters through existing lot.save and validators. This minimal compatible field fulfills the approved selected-coin notes requirement; existing collection-entry notes remain separate.
- All durable writes continue through the existing revision-checked writer, with request IDs, safe retries and the5MiB reserve rules. Do not bypass validation with a second record store.
- New calculator and new-bid defaults use companion preferences.currency. Research retains its existing per-search currency choice; label Settings currency Default bid currency, avoiding ambiguous competing defaults.
- Keep all prior audit guarantees for editor sessions, late replies, switching records, notification retries, timezone dates, merge drafts, Unicode terms and window coalescing.

## Shared implementation contracts

- extension/design-tokens.css supplies existing --bg/--surface/--card/--soft/--ink/--muted/--line/--border/--field/--accent/--accent-hover/--accent-soft/--on-accent/--focus/--error/--warning/--gold/--gold-line/--shadow and font tokens. Local UI CSS consumes rather than redefines palette tokens. Load this before local styles.
- extension/bid-tools.js exports mountBidCalculator(container, { currency='USD', onUseHammer=null, compact=false }={}). It builds its own controls, reads/persists house presets through the writer, and returns { setValues({ currency, hammerMinor, buyerPremiumBps }), destroy() }. Missing/null BP stays unknown. onUseHammer receives { hammer:{ currency,minor }, buyerPremiumBps }. UI hosts explicitly apply those values to editable draft controls and dispatch input events. extension/bid-tools.css styles the reusable widget.
- extension/navigation.js exports openResearchPanel(api=browserOrChrome), openSettings(section=''), openWorkspace(route='watchlist'). openResearchPanel must call the native API within the click gesture, using a pre-resolved current window ID or WINDOW_ID_CURRENT as supported; do not lose gestures behind unrelated awaits. Return a Promise<{ok:boolean, mode?:'side-panel'|'sidebar'|'window', message?:string}>. Native failure may use the validated background-owned lookup-window fallback. Do not close callers on failure.
- extension/source-menu.js exports mountSourcesMenu(container). It builds one accessible disclosure with official acsearch sign-in/search and CoinArchives free/Pro sign-in/ancient/world links. Fixed HTTPS URLs, noopener/noreferrer, no inferred account state. Its styles are in design-tokens.css.
- Settings is settings.html + settings.js + settings.css. It reuses theme.js, updates.js, core/backup.js and the existing writer. The workspace removes its old backup form/controller. settings.html#backup and #premiums expose their named sections.
- Popup and workspace consume the shared modules. Shared owners announce any interface changes to both UI owners before editing consumers.
