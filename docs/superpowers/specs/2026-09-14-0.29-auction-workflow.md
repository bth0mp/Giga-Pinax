Approved scope: all six findings and eight ideas from the 0.28 review. Sol implements; Astra reviews. Preserve schema version 1, browser IDs, the queued revision-checked command writer, the 5 MiB storage bound and existing records. No automatic bids, paid-data imports, cloud account, framework or new broad host permission.

## Shared contracts (frozen before parallel implementation)

Add optional lot fields, with omission preserving stored values, explicit null clearing the field, and supplied objects replacing it after validation. Existing legacy optional-field semantics remain unchanged.

```js
auctionContext: { pageUrl, canonicalUrl?, house?, saleId?, lotNumber? }
coinDetails: { photoUrls?: [], weightMg?, diameterHundredthsMm?, condition? }
provenanceNotes: [{ id, text, sourceUrl, recordedAt, auctionDate? }]
costEstimate: { currency, shippingMinor, paymentFeeBps, paymentFeeMinor, incrementMinor, minimumBidMinor }
```

URLs are HTTP(S), maximum 2048 characters; auction pageUrl is required and is the actual captured URL, never replaced by canonical. House/saleId/lotNumber each maximum 120. Photo URLs maximum two, explicitly entered by the collector; rendering is user-triggered, lazy, no-referrer, with an unavailable-image fallback and a clear external-host notice. Store links only, not binary images. Weight in integer milligrams 1..1,000,000; diameter in integer hundredths of mm 1..100,000; condition maximum 1000. Provenance maximum 20, UUID id, text 1..1000, required sourceUrl and canonical UTC recordedAt, optional valid YYYY-MM-DD auctionDate. Cost estimates use supported currency, nonnegative safe integer minor units, percentage 0..10000 bps, positive increment. Estimates do not change existing binding-exposure semantics.

`extension/core/lot-context.js` exports `normalizeAuctionUrl(url) -> string|null` and `findDuplicateLot(lots, candidate, excludeId?) -> lot|null`. Identity uses auctionContext.pageUrl (legacy sourceLinks only when clearly an auction identity), or complete normalized house/saleId/lotNumber. Remove fragment and known tracking parameters, preserve path case and identity query parameters. Never deduplicate merely by reference, title or canonical URL. Store lot.save enforces this in its serialized writer and returns `{ok:false,error:{code:'duplicate',message,existingLotId}}`; no implicit merging. Workspace gives Open existing coin.

`calculateBidCost(hammer, buyerPremiumBps, options={})` returns existing result style `{ok:true,value:{hammer,premium,hammerPlusPremium,shipping,paymentFee,total}}`. options shippingMinor/paymentFeeMinor default 0, paymentFeeBps defaults 0. Premium rounds half-up; payment percentage applies to hammer + rounded premium + shipping, then fixed payment fee is added. Use BigInt intermediates and reject unsafe output.

`calculateAffordableBid(budget,buyerPremiumBps,{shippingMinor=0,paymentFeeBps=0,paymentFeeMinor=0,incrementMinor=1,minimumBidMinor=0}={})` returns same result shape with highest affordable discrete hammer. Grid is minimumBid + n*increment. A zero-only/no valid affordable bid returns code no-affordable-bid. Fixed increment is user-entered, never inferred as a changing house schedule. Unknown premium stays unknown. All costs share input currency.

`mountBidCalculator` preserves its options and return API; extend setValues with `costEstimate`, and onUseHammer payload with `costEstimate` and `total`. New inputs live inside an optional fees/increments disclosure; preset updates subscribe by revision, keyed by normalized name, preserve dirty values, clean subscriptions on destroy, and guard stale replies. No settings.js interface change is needed.

`bid.plan` and `bid.place` accept optional top-level command.costEstimate, stored atomically on the lot under the same expected revision. Omission preserves; null clears. A supplied estimate's currency must match the bid amount currency. A preserved estimate in a different currency is unavailable for comparison until recalculated. Workspace owner adds this bounded store/test extension after core ownership is relinquished; never issue a separate metadata save around a bid command.

Capture buildResearchDraft, buildWatchlistDraftPayload and watchlistPayloadFromCapture carry auctionContext. Research has a separate context object; result cards preserve it. New capture replaces context; an explicit Clear auction context removes it. All save entry points share a synchronous single-flight guard; uncertain write retry reuses its request ID, and confirmed draft navigation retry reuses its draft ID. Opening research from workspace uses popup.html?panel=1&reference=<encoded reference>; this handoff is initialized after the research controller is ready.

Live acsearch curation is session-only and resets on a new lookup generation. Stable result IDs key exclusions. Count, range, median, comparison and copied summaries derive from the same included eligible rows. Period redraw preserves exclusions. Show included/excluded counts, Reset, all-excluded and no-prices states. Do not write provider rows to saved evidence.

Workspace queue: All open, Closing soon, Needs research, Planned, Active, Completed, plus All coins if useful. Closing soon means confirmed timed event in the next 48 hours; labels distinguish event start from lot deadline. Date-only events have no invented deadline. Needs research means open lot without reference; completed means won/lost/passed. Sort with nearest known time first, date-only after timed entries, unknown last. Keep search and selection/dirty-editor protections.

Workspace selected coin: separate Open auction and Research reference; editable auction house/sale/lot identity; coin measurements, condition and photo links; sourced dated provenance entries; preserved cost estimate. Compare 2–4 saved coins with session-only selection and individual labelled currencies. Comparison loads external photo URLs only after the user opens comparison; no automatic image requests on import or list rendering. No exchange-rate conversion or cheapest ranking.

Saved comparable end-date default uses the current date/year at runtime and never silently excludes future years. Correct README/navigation/calculator/research descriptions. Prepare official store listing/privacy/reviewer/asset packages. Preserve Firefox ID unless an actual store validation rejects it; an email-shaped add-on ID need not be a deliverable mailbox. Store publication requires available authenticated publisher accounts; do not claim signing/publication without results.
