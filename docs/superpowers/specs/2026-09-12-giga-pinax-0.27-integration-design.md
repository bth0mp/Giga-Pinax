# Giga Pinax 0.27 integration design

The user explicitly authorized combining Claude's installed Giga Pinax 0.26.0 with the previously approved and implemented auction companion, then publishing version 0.27.0 so that updating requires only Reload. This is an integration of the two existing designs, with the 0.26.0 repository at commit 6aae650 as the base. The implementation runs in an isolated worktree and is reviewed before replacing the installed build.

## Result

Keep Giga Pinax's name, Porphyry appearance, icons, shortcut, theme setting, reference parser, catalogue coverage, type lookup, recent references, resizable lookup window, session acsearch price tools, and CoinArchives links. Add Research, Calculator, and Watchlist tabs to its existing popup. Research contains the existing lookup interface. Calculator computes hammer plus buyer's premium. Watchlist shows upcoming auctions, due counts, and active exposure, with links into the companion workspace.

The full-page workspace contains saved comparables, watchlists, ranked alternatives, auction reminders, externally active bids, outcomes, collection history, and validated backups. Use Giga Pinax's visual tokens and remembered theme. Existing fictional sample UI is superseded by real Giga lookup; sample isolation and legacy preference migration remain safe.

## Source and data boundaries

Preserve the existing acsearch pipeline unchanged in scope: one collector action, the collector's own session, one results page, no pagination/background harvest, and results held only in the current view. The project records the user's report of acsearch approval in the 0.3 prices design. This is not a new grant of broader retention rights. No fetched acsearch sales, prices, row identifiers, or claims enter companion storage, drafts, exports, or evidence automatically.

Saved comparables use collector-entered or separately authorized observations, source links, sale identity, explicit conflict/inclusion decisions, and exact per-currency statistics. Their headline requires at least three sales. Giga's existing session price panel retains its own period, trend, last-sale and interpolation behavior; label the two datasets clearly. CoinArchives remains a user-opened search link.

Save to watchlist transfers only a reference, an ANS type label/link when available, or explicitly reviewed current-auction details. It opens a prefilled editor and requires Save before creating the lot. No live acsearch median becomes a bid recommendation or stored hammer.

## State and currency

Preserve `giga-pinax-preferences-v1`, `giga-pinax-theme-v1`, and `giga-pinax-labels-v1` in localStorage. Do not feed Giga's catalogue values through the old Price/RIC sample sanitizer. Keep the independent `auctionCompanion:v1` storage.local root, validated serialized writer, optimistic revisions, request ledger, bounded drafts, evidence, reminders and backups.

New companion preferences may initialize currency from the existing Giga preference, copying only a validated currency. Existing companion preferences win. Add CHF throughout companion money, record validation, forms, filters and exposure alongside USD/EUR/GBP. All four use integer minor units; never sum or convert across currencies. Calculator input remains hammer and BP only; no tax, shipping, FX or reverse budget.

Keep the Giga extension origin: same installed Brave directory and Firefox `giga-pinax@local.invalid`. Existing Giga preferences survive Reload. Companion records saved under another extension origin require its explicit JSON export/import; do not claim browser storage moves automatically. Backup disclosures distinguish companion records/settings from Giga lookup/theme caches.

## Runtime integration

Use one background module and one context-menu registrar. Preserve `giga-pinax-lookup` window-message behavior: the background must not answer that message, because only a lookup window should reply. Companion commands use an explicit whitelist or channel. Register the existing Giga lookup action together with Research highlighted coin and Track this auction; one menu setup must not remove another's entries.

Port the reviewed companion scheduler and command writer intact, including unknown-write resolution, stale-view rejection, reminder claim recovery, per-event notification isolation, late reminders, date-only defaults and explicit DST/time-zone confirmation. Alarms never fetch source prices. Notifications remain optional and system sound remains conditional.

Manifests retain Giga's existing three exact host permissions, shortcut, icons and browser-specific background declaration. Add storage, activeTab, scripting and alarms to existing contextMenus; optional notifications. No broad tabs, new hosts or offscreen permission. Firefox declares the actual user-initiated query/page-text categories. Both versions become 0.27.0; all new runtime assets belong in the deterministic package allowlist.

Sol UI owns popup/companion controller/CSS, workspace/current-lot/source launchers, related tests and installation copy. Existing lookup/price/catalogue/selection/theme modules stay unchanged except narrowly reviewed hooks. Root owns integration documents, native QA, release commits and promotion; Astra reviews design and source changes.

Retain the 205 passing Giga JavaScript tests and relevant companion tests. Replace superseded old popup expectations with integrated-controller behavior tests. Add meaningful tests for message routing, menu coexistence, CHF, independent preferences, and a watchlist transfer that rejects price-result fields. Re-run Python package tests and Firefox lint. Native Brave checks cover the combined popup/window, stubbed real lookup paths, no extra request on tab changes, saved workspace flows, storage persistence and reminders. No live account requests are needed for QA.

Publish only after checks and review: commit the integration, reconcile any new work on main without overwriting it, fast-forward or merge the reviewed result, rebuild the already-loaded Z: directory, verify source/package identity and version, and push the release commit to the existing origin. Do not force-push. The user then clicks Reload.
