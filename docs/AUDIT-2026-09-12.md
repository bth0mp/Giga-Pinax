# Giga Pinax audit — 12 September 2026

This audit covered the complete browser extension: catalogue parsing and ANS type lookup; acsearch price handling; CoinArchives launchers and the new Pro links; popup, context-menu, and workspace navigation; preferences; calculator arithmetic; watchlist, auction, bid, outcome, collection, and comparable records; reminders and notification recovery; backup and merge import; local-storage limits; manifests, permissions, updates, and deterministic packages; keyboard accessibility, dark and light themes, and responsive layout.

The final integrated source passed 355 JavaScript tests and 12 bundled Python tests with no failures or skips. An independent reviewer also passed 66 focused tests against the frozen implementation, plus 14 focused tests for the final pop-out error-handling change.

## Confirmed faults and fixes

The audit found and corrected faults in four main areas.

**Research and navigation.** Generic CoinArchives searches sent modern KM and Y references to the ancient section. Remembered price terms could cross catalogue boundaries, and long Unicode identifiers could break preference restoration. Concurrent popup and context-menu launches could lose the newest lookup or create duplicate windows. These paths now use the parsed coin section, a complete and Unicode-safe record identity, and one validated background-owned launch flow that drains to the latest request.

**Workspace state and accessibility.** The active route did not expose `aria-current="page"`. A successful save could erase text entered while the request was pending or cause the next edit to create a duplicate. The route state is now explicit, and editors track the submitted input generation, preserve newer input, and rebase it onto the returned durable record and revision.

**Reminders and storage.** Enabling notifications did not reconcile reminders already due; failed notification creation did not receive the intended short retry; date-only summaries compared UTC dates instead of the event timezone; and the alert-count limit could reject otherwise valid schedules after an event had been saved. Reconciliation now runs when alerts are enabled, failed deliveries retain their claim for a five-minute recovery attempt while relevant, and date-only events use their local calendar date. Scheduler replies are compact. Schedule-changing public writes project the complete reminder state, scheduler state, alert lifecycle, and 100 KB request-ledger headroom before committing. Internal scheduler and delivery transitions may spend that reserve. Only older reproducible internal ledger entries are pruned; public command replies remain available for idempotent retries. Reminder sets within the existing 5 MiB budget are supported, while unsupported new schedules are refused atomically before an event is committed. There is no unconditional 10,000-reminder storage guarantee. A collection already over the current budget may require the user to remove old events, reminders, or other saved data before another durable write.

**Backup and subscriber access.** Merge preview discarded unrelated local capture drafts; it now preserves local drafts while continuing to exclude drafts from imported backup data. CoinArchives Pro access is presented as three ordinary external links: sign in, ancient coins, and world coins. Giga Pinax does not receive credentials, detect account state, fetch paid data, or add CoinArchives host permissions. The free CoinArchives search remains available.

## Verification performed

The final combined run passed 355 of 355 JavaScript tests and 12 of 12 bundled Python tests, with no skips. Focused regression suites exercised catalogue routing, preference isolation and malformed input, concurrent lookup windows, workspace save races, alert reconciliation and delivery recovery, timezone boundaries, storage preflight, and backup merge behavior. An independent review of the frozen implementation passed another 66 focused tests, followed by 14 focused tests for the final pop-out error-handling change.

Package checks covered manifest identity and permissions, allowlisted contents, repeatable builds, and stable archive aliases. Firefox extension lint reported zero errors, warnings, or notices. The final source also installed successfully as a temporary extension in an actual Firefox 155 headless session through web-ext 10.6.

Native acceptance testing used an isolated Brave 153 profile and reported no page errors. It verified:

- a live ANS lookup for RRC 511/2b;
- logged-out acsearch guidance leading to sign-in;
- the CoinArchives Pro login link opening the official login form, without entering credentials;
- zero HTTPS requests during popup startup;
- a CHF 1,000 hammer plus 25% premium producing CHF 1,250, plus the unknown-premium state;
- watchlist and auction records, date-only timezone handling, planned versus externally active exposure, and a 100 hammer plus 25% premium active exposure of 125;
- a won outcome with hammer 90, invoice 120, and collection creation;
- alternative-group ordering, manual comparable evidence, and backup export plus merge;
- light and dark themes at the 400 × 600 popup size and a 390-pixel workspace, with no horizontal overflow.
- reloading the final packaged extension while preserving all six synthetic lots, collection records, and preferences, with no runtime or manifest errors;
- all editor races covered by the audit: newer typing followed by a second save without duplication, switching from one record to edit another, starting a new record while a save was pending, and preserving newer manual-evidence fields;
- two popup pages requesting pop-out simultaneously producing exactly one lookup window through the shared background flow;
- a failed pop-out response keeping the popup open with an accessible announcement, followed by a successful retry that opens the lookup window and closes its opener;
- the installed version displaying 0.27.2 and the update control using the stable package URL.

All native QA runs reported zero page errors.

## Limits

No paid CoinArchives account or authenticated acsearch Premium data was used, so signed-in Pro searches, paid archive content, and authenticated Premium price retrieval were not tested. Full Chrome and Firefox UI passes were not performed; Firefox coverage was limited to lint and a successful headless temporary installation. Audible operating-system notification sound was not verified because it depends on browser and system settings. These limits do not imply that every other possible input, browser state, or failure mode was proven.
